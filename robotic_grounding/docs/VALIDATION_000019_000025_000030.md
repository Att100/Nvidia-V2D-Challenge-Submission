# Grounding validation: episodes 000019, 000025, and 000030

Date: 2026-11-01

No full RL training was launched for these episodes. Original reconstruction and
baseline outputs were not overwritten.

## Canonical mapping

- `000019`: `object_001 -> mini_sweeper`, `object_000 -> mini_dust_pan`
- `000025`: `object_000 -> wooden_piece_1`, `object_001 -> wooden_piece_2`
- `000030`: `object_001 -> mini_sweeper`, `support_000 -> plastic_dish_rack`

All three source meshes are non-watertight. Preflight inventory and mapping
reports are under each episode's `grounding_run_v2/skill_baseline_v1/reports`.

## 000019 — REVIEW (retarget repaired, physical initialization unresolved)

The baseline scale sweep failed only because the left-hand IK entered a bad
orientation-constrained solution from frame 0. All 235 left-hand source frames
were valid. At scale 1.05, the original left wrist mean error was 246.96 mm.

The retained diagnostic candidate disables orientation costs for the left hand
only while retaining all joint-position targets. It passes the kinematic gate:

- left IK mean: 8.83 mm
- left wrist mean: 14.32 mm
- left contact MAE / recall: 2.03 mm / 80.6%
- right IK mean: 18.54 mm
- right wrist mean: 32.94 mm
- right contact MAE / recall: 2.42 mm / 88.7%

The case is not an independent-table-support case. The left hand contacts the
dust pan from frame 2 and the right hand contacts the sweeper from frame 16.
Object-only simulation therefore removes support that is part of the task. In
the current physical scene the sweeper moves 76.7 mm / 63.8 degrees and the dust
pan remains dynamically unstable. FlashCHORD readiness remains false.

Retained candidate:

`input/my_input/000019/grounding_run_v2/left_position_only`

## 000025 — REVIEW (frame-0 stability fixed, interaction penetration remains)

Both independently supported wooden pieces were moved to their nearest stable
attitudes on one table plane. The fixed per-object SE(3) corrections were then
applied to the complete object tracks and deterministically propagated to the
associated hands. The right hand changes association once because it handles
piece 1 and then piece 2. No contact optimization or finger-angle change was
used.

Object-only simulation now passes:

- piece 1 at 3 s: 1.29 mm / 0.59 degrees
- piece 2 at 3 s: 0.66 mm / 0.09 degrees
- object-object penetration: 0.0 mm
- object-support penetration: 4.64 mm

The complete physical replay still fails at the late object-combination event:
object-object penetration reaches 24.59 mm at frame 315. Hand-object penetration
is 9.61 mm. This needs an interaction-stage collision/contact repair before RL.

Retained candidate:

`input/my_input/000025/grounding_run_v2/object_frame0_common_plane/candidate_00_hand_se3`

## 000030 — REVIEW (static rack confirmed, rack-slot collision unresolved)

Treating `plastic_dish_rack` as kinematic keeps it fixed to numerical precision.
The original mini sweeper falls about 31.9 mm / 23.9 degrees into a temporarily
settled state. Reusing that 1 s pose as a new initial state is not a fixed point:
on a fresh rollout the sweeper leaves the slot and reaches 82.6 mm / 153 degrees
by 3 s. The settled-pose candidate is therefore rejected.

The kinematic reference remains visually coherent, but the collision geometry
does not provide a repeatable stable slot support. A rack/sweeper collision proxy
repair is required before RL. The failed settled candidate is retained as
evidence and is not promoted over the baseline.

Baseline:

`input/my_input/000030/grounding_run_v2/skill_baseline_v1`

Rejected fixed-point test:

`input/my_input/000030/grounding_run_v2/object_settled_static_rack/candidate_1s_hand_se3`

## Code changes used by this batch

- `ego_recon_to_sharpa.py` now has an opt-in, side-specific
  `--position_only_side` diagnostic mode. Default behavior is unchanged.
- `apply_object_se3_to_hands.py` now has opt-in
  `--allow-multi-object-hand` support for sequential multi-object interactions.
  It uses per-frame contact IDs and nearest-contact gap filling; default behavior
  remains the previous single-associated-object rule.
- Deliverable conversion supports an explicit alignment object so a static
  reconstructed support can define seating without changing canonical object
  order.
